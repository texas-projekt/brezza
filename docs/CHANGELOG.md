# Changelog

- Added a persisted native chrome theme preference with System, Light, and Dark modes. The main window and native settings/history/bookmark panels share the resolved palette, and toolbar layout now keeps the address control within its row at high DPI. Settings schema 1 files continue to load with the System theme.
- Polished native interaction details: restored the address cue banner on the inner edit control, added a visible active-tab close button, added compact controls for the minimum window size, fixed dark notice and panel colors, and measured localized panel buttons with the actual UI font.
- Added explicit native empty-state controls for history/bookmarks and darkened the settings panel's combo boxes so localized panel states remain readable in dark mode.
- Added a loading marker to the active tab while WebView2 navigation is in progress, with a smoke assertion that the marker disappears after completion.
- Reapplied main-window localization after top-level HWND creation so startup labels are not lost during the Win32 `WM_CREATE` lifetime boundary.
- Fixed tab-strip mouse-wheel direction handling so wheel scrolling activates the tab Core tracks, including negative signed wheel deltas.

## Unreleased

- Replaced the HTML/WebView2 browser chrome with native Win32 UI (ADR 0007): the window, tab strip, address/search field, navigation buttons, notice area, and settings/history/bookmark panels are real HWND controls owned by `Brezza.App` through P/Invoke, hosted in an STA message loop with a `SynchronizationContext` that keeps continuations on the UI thread.
- Hosted WebView2 content with `CoreWebView2Controller` directly against the browser window's HWND, with per-monitor DPI awareness, DPI-scaled fonts and controller bounds, and explicit rasterization scale. Removed the WPF `WebView2` control, the chrome surface, the `brezza.local` virtual-host mapping, and the versioned message bridge.
- Kept the trust boundary structural: content hosts disable the message bridge and register no message handler, so a remote page cannot address the browser; there is no browser-owned HTTP origin for a page to read or navigate into.
- Migrated `brezza://settings`, `brezza://history`, and `brezza://bookmarks` to native panels while keeping the logical URLs in the address field and session records; a tab entering an internal route releases its content host, and closing the panel returns the tab to the new-tab page.
- Moved search-provider presets into Core so the native settings panel and persistence share one definition, and added Core tests for the presets, host release, and the active-host surface contract.
- Removed the obsolete command-protocol parser, trusted-origin policy, chrome message types, and their tests; `ITabHost` now exposes view-surface operations (`SetVisible`, `SetBounds`, `SetRasterizationScale`, `Focus`) instead of a script bridge.
- Updated the Windows smoke harness to drive the real native controls (button commands, address-field input, tab-strip clicks and middle-click) and to assert native control state, tab items, and labels; the removed ChromeProfile/JS-toolbar path is gone.
- Updated packaging to produce `Brezza-<version>-win-x64-native.zip`, verify the x64 loader, drop the unused WPF/WinForms WebView2 assemblies, and start the extracted package to verify its native window, controls, and WebView2 surface. The previous `Brezza-0.1.7-win-x64.zip` is preserved.
- Fixed WebView2 tab-host event detachment so every controller subscription is removed when a host closes, and made the Windows smoke wait for the whole navigation before asserting the active tab's loading marker.
- Set the WebView2 content surface's default background to the current chrome palette so a page that has not painted yet no longer shows the runtime's default white, with a smoke assertion; a runtime System theme switch now re-themes the content surface and the open panel.
- Loaded the local stores and applied the saved theme and language before the first window frame, so startup no longer shows the system palette and re-themes afterwards; a theme switch now repaints the tab strip and labels together with the buttons, fields, content surface, and panel, and only reacts to real palette broadcasts.
- Removed the light erase flash in dark mode: owner-drawn buttons and flat edit fields suppress `WM_ERASEBKGND` (and buttons answer `WM_CTLCOLORBTN` with the palette backdrop), a WebView2 controller is created with the palette color and colored before its surface is visible, and a restored tab shows the palette instead of the new-tab page while its host is created.
- Made a theme switch repaint in one pass: the main window and the open panel redraw themselves and every child synchronously after the palette, content background, and language are in place, instead of invalidating controls one by one.
- Turned the theme into data: `NativeThemePalette` is two color-only instances (`Light`, `Dark`) instead of a light/dark switch per color, one shared `NativeThemeSource` replaces the per-window theme copies, backdrop colors and dark control styles are mapped in one place, and shared radii, spacing, and control heights moved into `NativeMetrics` outside the theme. The light and dark chrome renders pixel-identical to before.
- Fixed a flashing band below the toolbar while reloading: every source, title, and loading change re-rendered the new-tab page state, which re-laid out and erased the whole window even when nothing about the page changed. The window now does that only when the new-tab page actually appears, disappears, or changes text, and the Windows smoke reloads rapidly and asserts no relayout and no notice.
- Stopped showing "Page could not be loaded" when a load is replaced before it finishes. WebView2 reports a replaced load as unsuccessful (`OperationCanceled`, or `ConnectionAborted` once the page started streaming, sometimes only after the newer navigation already started). The tab host now compares navigation ids and waits one short grace period on an aborted load, Core treats a superseded or cancelled load as no failure and does not mark the tab failed, and a page that aborts with nothing replacing it still reports the failure.
- Passed the chrome's light/dark scheme to web content through `prefers-color-scheme` (WebView2 profile `PreferredColorScheme`), so built-in pages and form controls follow the chrome; pages with their own colors keep them. The Windows smoke asserts it from inside the page.
- Made the failure notice recoverable: Reload retries the address that failed, and once it loads the notice goes away, the tab leaves the failed state, and the window title returns to the page title. The Windows smoke creates the missing page, reloads through the notice's own action, and asserts all three.
- Returned focus to the browser window when a panel closes. Windows hands the foreground back when an owned window closes, but not after a modal confirmation was shown in between, so closing the history panel after clearing history left the browser unfocused and another application in front. The shell now activates the window and restores keyboard focus to the page, and the Windows smoke covers the clear-then-close path.
- Removed the minimize and maximize boxes from the browser panels. A panel is an owned window, so minimizing it left no taskbar button to restore it from; a fixed-purpose panel has no use for either box and stays resizable.
- Merged the managed assemblies into one `Brezza.exe` when packaging (ILRepack, pinned as a local tool), so the portable build is the executable plus the native WebView2 loader and the language packs (ADR 0009). `tools/package.ps1` gained `-SkipLaunchVerification` for CI, and its launch check now proves the merged executable starts with native controls and a WebView2 surface.
- Added GitHub Actions: `ci.yml` builds and runs the Core tests on every push and pull request; `release.yml` turns a `v*` tag into a packaged release, marking tags with a suffix such as `v0.2.0-beta.1` as pre-releases.
- Made the startup page a stored choice instead of a fixed behavior: Brezza now opens the new-tab page by default, and the native settings panel gained an "On startup" row that opens the pages from the previous session instead. Settings schema 3 stores the choice, and older settings files keep the new-tab default. The session is still saved at shutdown, so turning the option on restores what was last open; the Windows smoke runs both behaviors.
- Kept the active tab's close button reachable however many tabs are open, and stopped a crowded strip from shrinking its tabs into slivers. The close button used to hide itself once its tab fell below the minimum width, so a crowded strip left the user with no close button at all; it now shrinks onto its own tab instead of covering its neighbours, and it is never hidden. Tabs now stop shrinking at the minimum width and the strip scrolls sideways instead: the strip window itself is moved to scroll, so the tab control's items never overflow and its system scroll arrows never appear, and the view follows the active tab, which the wheel, a click on a partly visible tab, Ctrl+Tab, and a resize all move. The Windows smoke opens thirty tabs and asserts tabs keep the minimum width, the strip extends past the window, the system arrows never show, and the close button stays on the active tab and inside the tab band.
- Stopped a scrolling tab strip from erasing the controls beside it. The strip's window is as wide as its items so the tab control never scrolls them itself, but that width runs past the band the strip shows and over the new-tab button and the caption buttons, which sit below the strip in the z-order: scrolling left painted the frame colour over them and they vanished. The strip's window region is now clipped to the band, so it can no longer reach them, and the strip marks that it scrolls with a thin indicator under the tabs — a track spanning the band and a thumb whose width is the share of the strip that is visible — the only affordance the scrolling has, drawn only while the strip can scroll.
- Made a narrow tab keep its icon instead of a clipped word. Every tab leads with an icon: the page's favicon when it has one, otherwise the built-in globe glyph (`\uE774`) from the same Segoe icon font as the rest of the shell. A tab's label is always painted and ellipsized as the tab narrows, and the minimum tab width is derived from what a tab must still show — its leading icon, the room for that ellipsis, and the active tab's close button — instead of being a fixed constant. The Windows smoke asserts tabs keep that minimum width with thirty tabs open, and that the close button stays on the active tab and inside the tab band.
- Stopped a scrolled-out tab from painting over the caption row. The strip's window is as wide as its items so the tab control never scrolls them itself and never shows its system scroll arrows, but that width runs past the band the strip shows, so the tabs beyond the band used to bleed over the caption row beside the new-tab button whenever the strip was scrolled away from its end — most visibly when a new tab widened the strip before it became the active one. Painting and hit-testing are now both clipped to the band, so a tab out of view is neither drawn nor clickable there.
- Left a private tab one mark instead of three. A private tab used to lead with its favicon, then its private glyph, and carry a "private" word in its label; it now leads with the private glyph alone and keeps the page's own title, so the privacy mark is said once. The unused `tab.newPrivate` and `tab.privateLabel` locale keys are gone from both languages.
- Added per-tab favicons: `ITabHost` exposes `FaviconUri`, a `FaviconChanged` event, and `GetFaviconAsync`, and the WebView2 host fetches the image with the runtime's own favicon API inside the page's profile. Core records the URI on the tab (from the event, and synced again on navigation completion) and the shell's `TabFaviconCache` decodes it into a per-tab bitmap that survives its host sleeping or being released, repainting the strip when an icon arrives. A tab without a favicon keeps its title at the padding and shows no icon. Core tests cover the favicon state of any tab, clearing on a document without one, the navigation-completion sync, and fetching through the tab's own host.
- Stopped the new-tab button from sliding sideways as tabs are added. Tabs share the room left of the button, and the room was divided with a truncating division, so once the tabs filled the band the strip came out a few pixels short of it and the button walked left and right by that much on every added tab. The division now rounds up, so the strip fills the band as soon as the tabs reach it and the button stays where it is from then on; past that point the strip is wider than the room it shows and scrolls instead.
- Cut the repaints a scroll step costs. Moving the strip repainted it, clipping its window region repainted it again, and the clip invalidated the new-tab button and all three caption buttons even though a scroll changes none of them — six window repaints for one wheel notch. The strip is now moved and clipped without redrawing and invalidated once at the end, so the two never land between a move and a clip and the strip is never painted at the new offset under the old region, and the controls a scroll does not change stop repainting.
- Stopped the tab control from building its own system scroll arrows. The strip's window is as wide as its items so the control never scrolls them itself, but that width was estimated as the tab width times the count plus a fixed slack, which falls short of where the control's items really end: the items overflowed, the control built its `msctls_updown32` arrows, and the shell hid them again on every layout. Hiding a control the system keeps making is not the same as it never appearing — the arrows were built, and they flashed in the caption row. The window is now sized from the control's own last item rectangle, and it is widened before the items are laid out, so the items never overflow and the arrows are never built at all.
- Stopped a scroll step from painting the tab row twice. The strip was scrolled after the selection moved, and the tab control repaints for a selection change on its own, so the row was painted once still at the old offset and once at the new one — a flicker on every wheel notch. The strip is now scrolled before the selection moves, so both changes land in one paint, and the active tab's close button is positioned once, afterwards.
